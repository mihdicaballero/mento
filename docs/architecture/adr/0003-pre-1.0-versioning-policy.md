# ADR-0003: Pre-1.0 versioning policy — minors may break

Status: accepted (2026-08-26)

## Context

mento's de-facto public API includes private attributes (`beam._A_s_bot` and ~15
friends) documented as the way to read results. Supporting them forever would
make the roadmap's phases 2–3 prohibitively expensive. structuralcodes documents
this exact situation publicly: pre-1.0, the API is declared unstable and minor
releases may break it. The previous informal rule for mento was "never break the
public API"; this ADR supersedes it.

## Decision

While the version is below 1.0.0:

- **Patch** (0.x.Y): bug fixes and backwards-compatible additions only.
- **Minor** (0.X.0): may contain breaking changes. Every break is listed in the
  changelog with a migration note; where cheap, a `DeprecationWarning` shim is
  provided for one release cycle before removal (the pattern structuralcodes used
  for `GenericSection` → `BeamSection`).
- **1.0.0** declares the API stable; strict SemVer applies from then on.

The policy is published in the user-facing docs so downstream users (including
mako) can pin accordingly.

## Consequences

- The deprecated private-attribute compatibility layer of ADR-0001 has a defined
  end of life instead of living forever.
- Refactoring speed increases at the cost of asking users to read release notes
  before upgrading minors — acceptable at the project's current adoption stage.
- A changelog discipline becomes mandatory: no breaking change lands without its
  migration note.
